# 输入与结果界面契约

- 输入初始为一行视觉高度，支持多行；Enter 换行，Ctrl+Enter 发送，输入法 composing 期间不发送。
- 只有一个前台任务视图，多任务通过任务页选择；detach 产生空输入并允许新任务。
- 收起保留未发送草稿和运行中任务；完成结果收起后，下次为空输入。
- 输出保持可滚动、可复制；用户向上滚动后不被新输出拉回底部。
- 请求失败/程序启动失败时保留输入；未知提交状态必须区别于明确成功，不自动重试。
- UI 不解析进程编码、SSE 或业务成功条件；这些属于 Rust 执行端。
- 配置草稿由管理窗口级 `ConfigEditorSession` 拥有；动作/任务路由切换和隐藏窗口不销毁草稿，退出应用不承诺恢复。表单、JSON 与脚本编辑器仅提供展示和输入；bridge 只负责通信，Rust 拥有配置语义与持久化。
- JSON 与表单切换必须通过编辑会话转换，不要求先保存到磁盘。原生 JSON 解析使用 Rust 反序列化默认值，不校验执行完整性；类型/语法错误保留 JSON 输入并阻止切回。提交成功后旧表单缓存不能回写。
- 脚本草稿按动作 ID 和扩展名保留，各自维护源码与版本基线。重新载入配置或源码前，未保存修改需要明确丢弃确认；移除动作保留磁盘源码，切换类型保留通用设置及已有类型字段。新动作默认停用，完成配置后显式启用。
- 编辑会话串行执行异步操作，操作中禁用编辑和相关按钮；迟到加载不能覆盖新提交。配置和脚本分别保存，试运行只在必要保存成功后启动；部分成功分别报告，不能把已提交资源显示成未保存失败。
- 无效磁盘配置的回退警告与操作错误分开显示。恢复必须显式确认，传入观察到的磁盘版本；不可读文件不提供恢复覆盖入口。保存失败不自动重试。
- browser bridge 显著标记为模拟：它不执行本机程序、不发真实 HTTP、不产生原生通知。界面与原生共用组件；模拟不能作为原生执行验收证据。
- 瑞士国际主义风格：左对齐、清晰层级、规则间距、低色彩数量。悬浮输入不展示配置内部细节；日志等通过详情展开。
